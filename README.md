# SigmaGPT — AI-Powered Conversational Chatbot

SigmaGPT is a full-stack ChatGPT-style assistant built with React + Vite (frontend), Node.js + Express (backend) and MongoDB (conversation storage). Replies are generated by the **Groq** API (model `openai/gpt-oss-20b`), which the backend calls through the **OpenAI Node.js SDK** pointed at Groq's OpenAI-compatible endpoint `https://api.groq.com/openai/v1`.

Portfolio repository maintained by [Sukirti08](https://github.com/Sukirti08).

See [project upgrade notes](PROJECT_UPGRADE_NOTES.md) for context handling, validation, error handling, rate limiting, automated tests, and evaluation details.

## Features

- Chat interface with Markdown rendering, syntax-highlighted code blocks and a copy button
- Multiple conversations: create, list (newest first), reopen, delete (with confirmation)
- Conversations stored in MongoDB; follow-up questions use earlier messages as context
- Context limited by message count (default 20) **and** a character budget (default 24,000 ≈ 6,000 tokens)
- Configurable model, timeout, retries, temperature and output length
- Input validation, request-size limits, JSON error responses, per-IP rate limiting on chat
- Clear handling of AI errors (timeout → 504, provider rate limit → 429, bad key → 502, missing key → 503)
- Fast `503` responses when the database is down; health endpoint; clear start-up errors
- Dark interface with date-grouped conversation history (Today / Previous 7 Days / Older), message avatars, and a home screen listing what SigmaGPT can help with
- Copy, like and dislike buttons on every reply; ratings are stored with the message in MongoDB
- Model information menu (provider, model, status from `/health`), connection status indicator, loading indicator, error banner with Retry, mobile layout
- 39 automated backend tests (unit + integration) and an evaluation suite (`evaluation/`)

Conversations are scoped to anonymous browser sessions. The app currently has no account-based sign-in, PDF question answering, or live token streaming.

## Run on Windows (PowerShell)

### 1. Install the prerequisites

1. Install **Node.js 22 LTS** from https://nodejs.org (keep "Add to PATH" selected). Check in a new PowerShell window:
   ```powershell
   node -v
   npm -v
   ```
2. Install **MongoDB Community Server** from https://www.mongodb.com/try/download/community and select "Install MongoD as a Service". Check that it is running:
   ```powershell
   Get-Service MongoDB
   ```
   If it is stopped, run PowerShell **as Administrator** and execute `Start-Service MongoDB`.
   *Alternative:* create a free MongoDB Atlas cluster and use its connection string instead.

If PowerShell blocks `npm` with an "execution policy" error, run once:
```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 2. Configure and start the backend

```powershell
cd SigmaGPT-main\Backend
Copy-Item .env.example .env
notepad .env
```

Set at least:

```env
OPENAI_API_KEY=<your Groq API key>
MONGODB_URI=mongodb://127.0.0.1:27017/sigmagpt
```

All other settings are optional and documented in `.env.example`. Never commit `.env` or put the API key in frontend code.

```powershell
npm install
npm run dev
```

Expected output:

```
[db] Connected to MongoDB.
SigmaGPT backend running at http://localhost:8080 (model: openai/gpt-oss-20b)
```

Open http://localhost:8080/health. `"status":"ok"` and `"database":"connected"` mean the backend is ready.

### 3. Start the frontend (second PowerShell window)

```powershell
cd SigmaGPT-main\Frontend
npm install
npm run dev
```

Open the URL printed by Vite (normally http://localhost:5173). The status in the top-right corner should read **Online · openai/gpt-oss-20b**.

If the backend runs on another address, create `Frontend\.env` from `Frontend\.env.example` and set `VITE_API_URL`.

### 4. Production build check

```powershell
cd SigmaGPT-main\Frontend
npm run lint
npm run build
npm run preview
```

When using `npm run preview` (port 4173), add that origin to the backend: `FRONTEND_ORIGIN=http://localhost:5173,http://localhost:4173`.

## Automated tests

The backend tests use Node's built-in test runner; no extra packages are needed.

```powershell
cd SigmaGPT-main\Backend
npm run test:unit            # 23 unit tests, no services needed
```

The integration tests start the real API against a **separate** test database and a built-in mock of the OpenAI-compatible API (no Groq key or internet needed). Add this line to `Backend\.env` (the database is emptied by the tests):

```env
TEST_MONGODB_URI=mongodb://127.0.0.1:27017/sigmagpt_test
```

```powershell
npm test                     # all 37 tests (integration tests are skipped if TEST_MONGODB_URI is not set)
```

The `evaluation/` folder contains the black-box API suite, failure scenarios, browser tests and latency measurements used for the project report. See `evaluation/README.md`.

## API

| Method | Route | Purpose | Main error codes |
|---|---|---|---|
| GET | `/health` | Server, database and AI configuration status (200 or 503) | 503 |
| GET | `/api/thread` | List conversations, newest first | 503 |
| GET | `/api/thread/:threadId` | Messages of one conversation | 400, 404, 503 |
| DELETE | `/api/thread/:threadId` | Delete a conversation | 400, 404, 503 |
| PATCH | `/api/thread/:threadId/messages/:messageId/feedback` | Body `{ "value": "up" \| "down" \| null }`; rate or clear a reply | 400, 404, 503 |
| POST | `/api/chat` | Body `{ "threadId": "...", "message": "..." }`; returns `{ reply, threadId, userMessageId, messageId }` | 400, 413, 429, 502, 503, 504 |

All errors are JSON: `{ "error": "message", "code": "CODE" }`.

## Configuration summary

| Variable | Default | Purpose |
|---|---|---|
| `OPENAI_API_KEY` | — | Groq API key; required for replies (missing → HTTP 503). The `OPENAI_` prefix is kept because the OpenAI SDK is the client. |
| `MONGODB_URI` | — | Required; the server exits with a clear message if missing or unreachable |
| `OPENAI_MODEL` | `openai/gpt-oss-20b` | Model served by Groq |
| `OPENAI_BASE_URL` | `https://api.groq.com/openai/v1` | Optional override (tests point it at a local mock) |
| `OPENAI_TIMEOUT_MS` / `OPENAI_MAX_RETRIES` | 30000 / 1 | Request timeout (→ 504) and retries |
| `OPENAI_TEMPERATURE` / `OPENAI_MAX_OUTPUT_TOKENS` | model default | Optional generation settings |
| `CONTEXT_MAX_MESSAGES` / `CONTEXT_MAX_CHARS` | 20 / 24000 | Conversation context sent to the model |
| `MAX_MESSAGE_CHARS` / `BODY_LIMIT` | 8000 / 100kb | Input limits |
| `RATE_LIMIT_MAX` / `RATE_LIMIT_WINDOW_MS` | 20 / 60000 | Chat requests per IP per window |
| `PORT`, `FRONTEND_ORIGIN`, `DB_CONNECT_TIMEOUT_MS` | 8080, http://localhost:5173, 5000 | Server settings |

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `[startup] MONGODB_URI is missing` | `Backend\.env` does not exist or lacks the variable. Copy `.env.example` to `.env`. |
| `Could not connect to MongoDB within 5000 ms` | MongoDB is not running (`Get-Service MongoDB`; `Start-Service MongoDB` as Administrator) or the Atlas URI / IP allow-list is wrong. |
| `Port 8080 is already in use` | Another backend is running. Close it (find its process ID with `netstat -ano` and look for `:8080`) or change `PORT` and set `VITE_API_URL`. |
| Red banner "Cannot reach the SigmaGPT backend" | The backend is not running or `VITE_API_URL` is wrong. |
| "OPENAI_API_KEY is missing" (503) | Set the key in `Backend\.env` and restart the backend. |
| "The AI provider rejected the server's API key" (502) | The Groq key is wrong or revoked; create a new one in the Groq console. |
| "The AI service is busy or the usage quota was reached" (429) | Provider rate limit or no remaining credit. Wait, or check billing. |
| "The AI model took too long to respond" (504) | Slow network or model; increase `OPENAI_TIMEOUT_MS`. |
| "Too many requests" (429, `RATE_LIMITED`) | SigmaGPT's own limit; wait for the time shown or raise `RATE_LIMIT_MAX`. |
| Browser console shows a CORS error | The frontend runs on an origin not listed in `FRONTEND_ORIGIN`. |
| `npm test` reports that no test files were found | Node.js is older than 22. |

### Conversation privacy

The frontend stores a random session token in browser storage and sends it as an
`Authorization: Bearer <token>` header on chat requests. Each conversation is
available only to the browser session that created it. Another browser or a
cleared browser profile starts a new session. The backend stores only a hash of
the token.

Conversations created by versions without session ownership stay in MongoDB,
but are excluded from normal API access because they have no known owner.
Overlapping chat submissions for the same conversation can return HTTP 409.
Wait for the current reply, then retry the message.
